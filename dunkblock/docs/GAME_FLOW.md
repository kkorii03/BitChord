# 덩크시티 게임 흐름 메모 (블록 자동화 관점)

출처를 구분합니다. **[사용자]**는 사용자 설명, **[측정]**은 이 프로젝트의 실측, **[미확인]**은 아직 확인 못 한 것입니다.

## 확인된 사실

| 항목 | 내용 | 출처 |
|---|---|---|
| 경기 형식 | 3:3 | [사용자] |
| 조작 선수 | 경기 전에 고른 **내 선수 한 명만** 조작(자동 전환 없음) | [사용자] |
| 블록 입력 | 블록 버튼을 누르는 **즉시** 블록 점프 | [사용자] |
| 블록 타이밍 감각 | 슛은 **생각보다 빨리** 뛰어야 막힘 | [사용자] |
| 블록 범위 | 대부분 정면 180°, 일부 정면+측면, **올드 르브론 360°** | [사용자] |
| 사용 캐릭터 | 올드 르브론(360° → 각도 판정 없이 거리만 보면 됨) | [사용자] |
| 블록 성공 빈도 | 한 판에 1번도 어려움 | [사용자] |
| 화면 캡처 | 경기 화면 캡처 가능(검은 화면 0.4%), 경기 중 약 120fps | [측정] |
| 자동 블록 입력 | 오버레이 대리 조이스틱으로 이동 유지 + 블록 탭, 연습 모드에서 실제 블록 점프 확인 | [측정+사용자] |
| 화면 위치 (SM-S928N 가로 3120x1440) | 조이스틱 중심 (645, 1108), 블록 버튼 (2774, 1203) | [측정: ⑦ 보정] |

## 아직 모르는 것

- 블록 성공 시 화면 표시("BLOCK" 등) 여부 [미확인, 사용자 기억 없음]
- 슛 종류별 블록 가능 구간(동작 시작 후 몇 ms) [미확인 → 영상·실험으로 측정]
- 블록 버튼을 누른 뒤 점프 애니메이션이 보이기까지의 게임 지연 [미확인]
- 서버 판정 방식(핑 20~60ms의 영향) [미확인]

## 설계에 주는 의미

1. **"생각보다 빨리" + "누르면 즉시 점프"** → 공이 손을 떠나는 순간(release)에 반응하면 늦다. **드리블을 멈추고 공을 잡는 순간**(`dribble_last_bounce` 이후)과 **공을 들어 올리기 시작하는 순간**(`shot_motion_start`)을 가장 이른 신호로 쓴다. 영상 파이프라인에서 이 두 신호가 가장 정확하게 잡힌다(합성 검증 오차 0~3프레임).
2. **내 선수 고정 + 르브론 360°** → "내 선수 근처의 공 가진 상대"만 보면 되고 각도 판정은 생략할 수 있다. 먼 상대의 슛은 무시한다(거리 조건).
3. **성공 사례가 드묾** → 사용자 플레이만으로는 정답 데이터가 부족하다. 랭커 영상의 블록 성공 장면과, 비공식 모드에서 앱이 타이밍을 바꿔 가며 시험하는 방식(사용 가능한 모드 확인 필요)을 함께 쓴다.
