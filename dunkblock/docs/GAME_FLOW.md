## 아직 모르는 것

- 블록 성공 시 화면 표시("BLOCK" 등) 여부 [미확인, 사용자 기억 없음]
- 슛 종류별 블록 가능 구간(동작 시작 후 몇 ms) [미확인 → 영상·실험으로 측정]
- 블록 버튼을 누른 뒤 점프 애니메이션이 보이기까지의 게임 지연 [미확인]
- 서버 판정 방식(핑 20~60ms의 영향) [미확인]

## 설계에 주는 의미

1. **"생각보다 빨리" + "누르면 즉시 점프"** → 공이 손을 떠나는 순간(release)에 반응하면 늦다. **드리블을 멈추고 공을 잡는 순간**(`dribble_last_bounce` 이후)과 **공을 들어 올리기 시작하는 순간**(`shot_motion_start`)을 가장 이른 신호로 쓴다. 영상 파이프라인에서 이 두 신호가 가장 정확하게 잡힌다(합성 검증 오차 0~3프레임).
2. **내 선수 고정 + 르브론 360°** → "내 선수 근처의 공 가진 상대"만 보면 되고 각도 판정은 생략할 수 있다. 먼 상대의 슛은 무시한다(거리 조건).
3. **성공 사례가 드묾** → 사용자 플레이만으로는 정답 데이터가 부족하다. 랭커 영상의 블록 성공 장면과, 비공식 모드에서 앱이 타이밍을 바꿔 가며 시험하는 방식(사용 가능한 모드 확인 필요)을 함께 쓴다.

## 실제 영상에서 확인한 것 (2026-11-10, 사용자 화면 녹화 3개)

녹화본: 갤럭시 화면 녹화, 2340x1080, **약 120fps 가변 프레임레이트**(프레임 간격 2~33ms). 길이 각 5~7초. 모두 **게임 리플레이 재생 화면**이다.

| 항목 | 관찰 | 출처 |
|---|---|---|
| 리플레이 속도 | 녹화 4.0초 동안 샷 클락도 4.0초 감소 → 1배속 | [측정: 샷 클락 판독] |
| 리플레이 조작 | 시작 직후 일시정지 구간, 되감기(03:47→03:45) 구간이 있음 → 타이밍 분석에서 제외해야 함 | [측정] |
| 공 모양 | **검정 바탕 + 노란 면**, 원본 지름 약 36px. 노란 부분 약 40%, 검정 약 46% | [측정] |
| 공 색만으로 찾기 | 노란 영역이 관중석·유니폼·신발·주황 포지션 배지(SF)에도 많음. 움직임 조건을 넣어도 표본 32개 중 실제 공은 약 7개(정밀도 약 20~25%) → **색 기반 공 추적은 실제 영상에서 쓸 수 없음** | [측정] |
| 동작 표시 글자 | 선수 머리 위에 **"블록"**(흰 손 아이콘, 약 1초 유지), **"드리블 불가"**(빨간 글자) 같은 표시가 뜬다 | [측정: 화면 확인] |
| 샷 클락 원 | 샷 클락 5초 미만이면 공 가진 선수 발밑에 빨간 원과 숫자가 뜬다 | [측정: 화면 확인] |
| 거리·방향 표시 | 선수 주변에 2m / 2-3m / 3-4m / 4-5m 거리 표시와 청록색 부채꼴이 보인다(의미 미확인) | [측정: 화면 확인] |

의미: 공을 직접 쫓는 대신 **게임이 띄우는 표시(블록 글자, 샷 클락 원)**를 기준 신호로 쓰는 편이 훨씬 신뢰할 만하다. "블록" 표시가 시도인지 성공인지는 [미확인].
