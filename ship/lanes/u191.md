   not carry. Restoring it would need a cross-caller re-integration of `leadHero`. The fork's
   `LARGE_CARD_CORNER` styling is still used by the other shelves.
2. **Upstream `repeatAllStash` queue-level stash** — not integrated. The fork uses
   `autoplayBeforeRepeatAll` (setting-level hold) for the same repeat-all autoplay behaviour; the
   auto-merge left only an orphan `repeatAllStash = emptyList()` assignment referencing undeclared
   properties, which was removed.
3. **`ArtworkMeshBackdrop` live blur** — upstream removed the `RenderEffect` blur and baked it into
   the mesh; the fork's `reduceDynamicBlur`/`canBlur` guard is therefore moot and was dropped. The
   fork's `lowPower` fade guard is kept.
4. **`CanvasArtworkPlayer` `isPlaying` refresh check** — the fork deliberately plays the clip
   continuously in the foreground, so its `foreground`-based `shouldRefreshFrames` subsumes upstream's
   `isPlaying` check.
5. **Korean wording** — for keys upstream re-worded, the Korean was updated to the new meaning
   (e.g. `prefer_music_only_subtitle` now describes audio-version playback + ahead conversion).

### Addon fix in `0c6854e57`

- `AddonClient.body()`/`fetch()` gained `restOnGateway: Boolean = true`; `manifest()` passes `false`,
  so a 503 on the manifest no longer sets the client-wide `holdOffUntil`. The host rest is still
  recorded through `HqHostTracker`, so the source cooldown is unchanged, but a search or stream that
  would have answered is no longer blocked by a metadata endpoint being down.
- `AddonSource.health()` now calls `client.checkAuth()` when the manifest requires auth, before the
  `/search` probe. A device the auth service refuses is reported as `Rejected` (or `Unreachable` for
  `AddonUnavailable`) with the service's own message, instead of reading `Ok` while every search
  fails.
