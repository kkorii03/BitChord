== 2차 작업 (현재 브랜치 = 1차 결과) ==
검토 지적을 전부 고칠 것. 틀렸다고 판단하면 근거와 함께 요약에.
Opus 추가: 비디오 노래 자동 재생 기능(별도 브랜치에서 개발 중, 나중에 합침)은 자동 재생을 채울 때 'video-radio: seed=<id> mode=<video|music> picked=N from=... dropped=... fallback=...' 줄을 찍음 → A1~A3 모드 판정은 이 줄(시드 id 일치)로, 붙은 곡 제목은 기존 'autoplay: +radio N +similar N +fav N (제목 - 가수 | ...)' 줄로. 이 줄이 없으면(아직 기능이 안 합쳐진 빌드) SKIP 사유 'no video-radio line'. scenario.py 판정 함수에는 로그 샘플로 돌리는 단위 테스트(pytest 없이 python -m unittest 로 실행 가능한 tests 파일)를 추가.
검토 지적:
VERDICT: ISSUES 9
- HIGH `app/src/devDebug/java/com/music/bitchord/debug/DebugScenarioReceiver.kt:30` — The worker Thread calls `MediaController.setRepeatMode/sendCustomCommand/setMediaItems`, but MediaController is bound to the main looper and throws `IllegalStateException` off it, so B3 and play-local never execute. Fix: post all controller calls to the main looper and keep only MediaStore/IO work on the worker.
- HIGH `scripts/smoke/scenario.py:125` — `mode_of` can only learn video/music from the target track's `track-summary`, which the app writes when that track ends; A1/A2/A3 slice only the first 60 s, so all three always return SKIP. Fix: determine mode from a per-play log or add/wait for a log that identifies the current track's mode.
- MEDIUM `scripts/smoke/scenario.py:388` — `render`/exit treat a report with zero PASS and all SKIP as "PASS" and exit 0, so CI goes green even when nothing was verified. Fix: report PASS only when at least one scenario passed and none failed; otherwise use SKIP/FAIL with a nonzero exit.
- MEDIUM `scripts/smoke/scenario.py:110` — `autoplay_titles` takes text after the last `(`, so a title containing parentheses yields one bogus title, and it also accepts `autoplay: dropped ... (cover/karaoke)` as attached, corrupting A1/A2 counts and A3 cover detection. Fix: parse the list after the `+fav N (` prefix and ignore lines containing `autoplay: dropped`.
- MEDIUM `scripts/smoke/scenario.py:261` — A9 passes on `finish_delta` alone even when no `play: ... reason=AUTO` exists (`handedOff=false`), and the slice starts before play-local so a prior scenario's crossfade can be used. Fix: start the A9 slice after play-local and require an AUTO play of one of the pushed tracks.
- MEDIUM `scripts/smoke/scenario.py:319` — C5 measures from the command marker instead of the 7Q play timestamp and accepts any non-7Q play, including a version swap or a delayed prior play, as the next track. Fix: start at the 7Q play line when present and require a distinct queue transition after it.
- MEDIUM `scripts/smoke/scenario.py:158` — A1/A2 with zero attached titles are reported SKIP, but the stated criterion (`attached >=5`) makes that a FAIL once mode is known, hiding an autoplay regression. Fix: SKIP only when mode is unknown and FAIL when titles are empty or fewer than five.
- LOW `scripts/smoke/scenario.py:348` — C6 scans the unfiltered system logcat, so an unrelated process's `FATAL EXCEPTION`/`ANR in` in the window fails BitChord. Fix: filter C6 lines to the app's PID/package before counting.
- LOW `scripts/smoke/run.sh:305` — The fixed `/sdcard/Music/bitchord-smoke-*.flac` names are overwritten and later deleted, destroying any pre-existing files with those names. Fix: use unique names or a temp subdirectory and delete only files created by this run.
