BitChord 안드로이드 앱(Kotlin). 검색은 grep/git grep(rg 없음), 저장소 전체 목록 출력 금지(큰 출력 뒤 멈추지 말고 끝까지 작업). 기준 브랜치 task/video-radio-base(= 사용자 폰 vc85 + 이전에 만든 순수 규칙 파일 shared/.../data/videoradio/VideoRadioPolicy.kt 와 테스트, 아직 앱 어디에도 연결 안 됨).
사용자 요청(가장 중요한 기능): 유튜버가 커버한 '비디오 노래'(예: '아카네 리제 - Not a Dream', 오화요 커버, 팬 클립 채널 업로드)를 들으면 자동 재생(∞)이 그런 비디오 노래 위주로 채워져야 함. 지금은 ① 일반곡(마룬5 Maps, 이매진 드래곤스 등)으로 빠지거나 ② 커버 제외 규칙에 전부 걸려 0곡 → 같은 곡만 반복(폰 로그 10-30 22:24: 'radio:k4b7dnA8z0I ok' → 'autoplay: dropped 37 cover/karaoke rows' → 'dropped d0Idllfw7l4 (no metadata)' → 추가 0곡, 전체 로그 'dropped N cover' 362회 vs '+radio' 107회). 설계 문서 = ship\design-video-radio.md 와 같은 내용(아래 요약), ship\FIXLIST.md 84번.
설계(사용자와 결정됨): ① 모드 판단: 시드가 비디오 노래(YouTube 영상, 채널이 '- Topic'·공식 아티스트 채널 아님, 공식 MV 아님: 커버·라이브·노래 영상)면 비디오 노래 모드, 아니면 일반곡 모드. VideoRadioPolicy.kt 의 기존 함수를 먼저 읽고 재사용(맞지 않으면 고치고 테스트도 고침). ② 비디오 노래 모드 후보: youtube.com 영상 믹스(list=RD<videoId>, 기존 youtube.com 경로·프록시 규칙 따름) + 시드 채널의 다른 노래 영상 + 지금 라디오 결과 중 커버·노래 영상. 걸러내기: 90초~8분, 쇼츠 제외, 노래 표시(커버·cover·불러봤·歌ってみた·live·라이브·노래·sing) 또는 음악 분류, 잡담·브이로그·리액션·하이라이트 모음 제외, 노래방·8비트·피아노·Inst/MR 제외, 최근 50곡 안에 들은 영상과 같은 곡 다른 커버 연속 금지. 비율: 같은 가수(채널) 1 : 다른 가수 2, 같은 가수 연속 최대 2곡. 공식 일반곡은 섞지 않음 — 후보가 바닥나면 그때만 기존 자동 재생. ③ 이 모드에서 붙은 곡은 MV→노래 버전 교체(song version)를 건너뜀(공식 MV 가 섞이면 기존 규칙). ④ 일반곡 모드는 지금처럼 커버 제외 유지(일반곡 → 커버로 새지 않기). 모드 판단은 시드 기준이고 사용자가 직접 고른 곡·직접 넣은 대기열은 절대 바꾸지 않음(자동 재생 꼬리에만 추가). ⑤ 어느 모드든 거른 뒤 0~2곡이면 단계적 대체(같은 모드 다른 재료 → 기존 자동 재생 → 그래도 0이면 대기열 '자동 재생' 칸 문구 '추천 곡을 찾지 못했습니다', values-ko 합니다체). 자동 재생 켜짐 + 반복 꺼짐에서 큐가 비어 같은 곡이 반복되는 일 없게. ⑥ 스위치: 대기열 화면 자동 재생 칸 아래 '비디오 노래 이어 듣기'(기본 켜짐) + 설정 > 재생 같은 키. 끄면 기존 동작. ⑦ 후보는 대기열 남은 곡이 3곡 이하로 줄 때만 가져오기(이벤트), 폴링 없음. 함께 듣기 중엔 끔. 오프라인이면 다운로드된 비디오 노래만. ⑧ 로그: 'video-radio: seed=<id> mode=<video|music> picked=N from=<mix|channel|radio> dropped=<사유별 수> fallback=<단계>'.
할 일: 기존 자동 재생 흐름(autoplay 로그 찍는 곳, data/taste/AutoplayOrder·Recommender·SimilarCandidates·TastePool, AutoplayQueue, radio 요청)을 먼저 읽고 요약에 흐름 5줄 → 위 설계대로 연결 → 테스트.
테스트: 모드 판단(오화요 커버·아카네 리제 팬 클립 = video, '- Topic' 곡·공식 MV = music), 비디오 모드 걸러내기·비율·연속 제한, 일반곡 모드 커버 제외, 0곡 대체 단계 — 순수 함수 단위 테스트. shared 테스트 클래스 이름과 app 테스트 이름을 요약에(CI 목록에 Opus가 추가).
반드시: 배터리 우선(주기 폴링·타이머 금지, 이벤트 기반), 요청 수 최소. 바꾼 함수의 모든 호출부와 타입 확인. 기존 코드 의도(주석)를 지우면 요약에 이유. 반복 '전체' 중 자동 재생 꺼짐 설계 유지. 업스트림 v1.8.1 코드 쪼개기·삭제 금지(한국 기능은 새 파일에, 업스트림 파일엔 연결 몇 줄만). 제약: .github/, keys, 서명 수정 금지. 마지막에 10줄 이내로 요약: 수정 파일 / 핵심 변경 / 테스트 결과 / 미해결 문제.
