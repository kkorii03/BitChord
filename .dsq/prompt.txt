HIGH — TelegramClientGate.kt:27 (wired via TelegramClientManager.kt:67,70-76) — because `playbackActive` comes from the global `PlaybackActivity`, the new independent term opens/holds a TDLib client for any local/YouTube playback, including buffering, even before Telegram is configured, wasting battery and violating the plan's “텔레그램 재생·다운로드” rule. MEDIUM — TelegramClientManager.kt:298 (with :164) — when Close/LogOut misses the 5s/20s deadline the code leaves `closing=true` and the native client alive with no retry or escalation, so a hung TDLib stays open in the background forever and `startClient` remains latched shut. Fix: on timeout schedule an event-driven retry or safely force-reset the handle and bump the generation instead of leaving the state latched indefinitely.
LOW — TelegramClientManager.kt:306-315 (with :225-232) — `finishClosed` does not advance `generation`, so callbacks already queued from the just-closed client still pass the generation checks and run `onUpdate` after cleanup, letting a queued `Closing` overwrite the CLOSED/error state (and potentially re-run auth handlers). Fix: increment `generation` in `finishClosed` so queued updates from the closed client are dropped.
LOW — TelegramClientManager.kt:428-434 (with TelegramSettingsScreen.kt:157-161) — the new hard failure for a missing/unreadable database key has no recovery path because logout/reset is only offered in READY, so a Keystore invalidation permanently bricks Telegram with no in-app reset. Fix: expose a reset/delete-session action on this error state and mint a fresh key only after the unreadable session is removed.
