BitChord 안드로이드 앱(Kotlin). grep/git grep(rg 없음), 전체 목록 출력 금지. 기준 task/integrate.
버그(폰 로그로 증명): 전에 들은 곡은 AudioCache 에 저음질(opus 132kbps) 사본이 있음. 재생 시 캐시로 바로 재생 -> QualityUpgrade.adoptUnresolved '...from cache and was never resolved; looking for a better copy' -> 무손실 찾고 HqAudioVerify 통과 -> PlaybackService.kt 약 5778~5792 줄에서 SourceResolver.rememberOriginal 후 'upgrade found ... kept for next play; no mid-song swap'. 그런데 다음 재생도 또 캐시로 재생돼서 같은 일이 반복(하룻밤 35회), 무손실로 바뀌지 않음. 손으로 누를 때만 바뀜.
고칠 것: 곡 시작 시 캐시를 쓸지 정하는 곳을 찾아서, (캐시 사본이 무손실 아님) AND (SourceResolver 에 검증된 더 좋은 원본이 기억돼 있음) 이면 캐시 대신 resolve 해서 그 원본으로 재생. 판단은 순수 함수 하나로 빼서 테스트.
반드시 지킬 것: ① 기억된 원본 resolve/재생이 실패하면 기존 캐시 사본으로 즉시 되돌아가 재생(무음·튕김 금지, 오프라인이면 캐시 그대로). ② 저음질 캐시 항목은 무손실 사본이 hq-cache 에 다 받아진 뒤에만 지움(먼저 지우지 말 것). ③ 곡 재생 중 교체(mid-song swap) 정책은 바꾸지 말 것. ④ rememberOriginal 이 메모리에만 있으면 앱 재시작 후에도 쓰이도록 기존 저장 방식으로 작게 보존(없으면 요약에 적기). ⑤ 다운로드된 곡·커버 곡·MV 판정 경로는 건드리지 말 것. ⑥ 배터리: 폴링·타이머 금지, 이벤트 기반. ⑦ 판단 결과를 TrackLog 한 줄로 남김: 'hq-replay: <id> cache=<형식> remembered=<형식> -> resolve|cache'.
테스트: 판단 함수 단위 테스트(캐시 저음질+기억 있음 -> resolve, 캐시 무손실 -> cache, 기억 없음 -> cache, 오프라인 -> cache). 바꾼 함수의 모든 호출부와 타입 다시 확인. 새 app 테스트 이름을 요약에 적을 것.
제약: .github/, keys, 서명 수정 금지. 10줄 이내 요약: 수정 파일 / 핵심 변경 / 테스트 결과 / 미해결 문제.
