- HIGH — `app/src/main/java/com/music/bitchord/data/settings/AppSettings.kt:1149` — `existingInstall` is false once onboarding is complete, so a normal app update writes the HQ switches as `true` and leaves automatic replacement/prefetch enabled, the opposite of the required upgrade default. Fix: derive the migration default from pre-update data presence (e.g. `prefs.all.isNotEmpty()`), not `existingInstall`, and test `reload()`, not just the pure helper.
- HIGH — `app/src/main/java/com/music/bitchord/playback/smart/LyricsTiming.kt:187` — HQ is skipped only when `base.byAi`, so an `auto` measurement made against the file (or the old file, because `resetSongCheck` at `:1558` clears AI but not `auto`/`autoVersion`/`syncCheckVersion`) remains and the saved HQ map is stacked on top, double-shifting lyrics after replacement. Fix: clear the auto/sync fields on HQ replacement and/or skip HQ for any base already on the file clock.
- MEDIUM — `app/src/main/java/com/music/bitchord/playback/smart/HqAudioVerify.kt:254` — `completeEnough` uses a fixed 90s window (>=81s), so a fully decoded track shorter than ~81s is treated as truncated and can never be HQ-verified; its reference is also re-decoded for every candidate. Fix: treat reaching EOF/known duration as complete and reject only reads cut short before the requested window.
- MEDIUM — `app/src/main/java/com/music/bitchord/data/settings/AppSettings.kt:2826` — for known keys the sanitizer returns the original value when it has the wrong type (e.g. a backup with `playback_speed` typed as a string), so `reload()`'s `getFloat`/`getString` throws `ClassCastException` after prefs were already cleared. Fix: drop the key unless the value has the expected type before clamping.
- MEDIUM — `app/src/main/java/com/music/bitchord/download/HqLibraryUpgrade.kt:237` — with prefetch now `allowMetered=false`, a metered pass is refused by `Downloads.enqueue`, then `settle` removes each target and appends the next worker, so the whole prefetch plan is churned through (up to 500 WorkManager jobs) on mobile instead of waiting for Wi-Fi. Fix: skip prefetch targets when `downloadsAllowedNow` is false or run the prefetch half under an unmetered constraint.
