작업: 가사 싱크 '줄 보정(refine)' 단계 추가 — Opus 설계, 수학은 아래 그대로 구현. 기준 task/integrate. 검색은 grep/git grep(rg 없음), 전체 목록 출력 금지.

배경(폰 실측 10-26 vc76, Whisper 채점, 커버 20곡): 기준(base)이 measured(원곡과 크로마 정렬, 일치율 94~100%)인 곡도 줄 오차가 남는다. 예: ZjZRLy3A3QA measured shift=0 → 모든 줄 -0.20초(const), Y3reGsQn52g measured 500 → +0.26 const, qQNbfxDLxq0 ai -454 → -0.24 const, -LqfikBILXs measured -1099 → -0.21 const, xK5bBgpt4XA none → +0.19 const.
원인: measured 는 '커버 ↔ 원곡' 시차만 고친다. 가사 제공처(lrc.red 등)의 줄 시각 자체가 원곡 보컬보다 0.2초쯤 이르거나 늦으면 그대로 남는다. 합격 기준: |오차| 중앙값 ≤ 0.2초, 0.3초 이내 줄 ≥ 90%.

설계(LyricsTiming / LyricsController 쪽, 기존 measured/ai 계산은 바꾸지 말 것 — 그 위에 얹는 마지막 단계):
1. 입력: (a) 최종 적용 시각의 가사 줄들(base map + manual 적용 후 화면에 나가는 시각), (b) 지금 재생 중인 소리의 받아쓰기 단어(LyricsWordAlign.Heard: 단어, 시작ms) — 이미 있는 AI 받아쓰기 경로(AiLyrics/Deepgram, heardWords)를 재사용. 받아쓰기가 없는 곡이면 이 단계는 아무것도 안 함.
2. 줄마다 잔차: 줄의 첫 단어(정규화: NFKC, 소문자, 글자·숫자만)가 받아쓰기 단어와 일치하는 곳을, 그 줄의 표시 시각 ±1.5초 안에서 가장 가까운 것으로 찾는다(반복 후렴 오매칭 방지: 가까운 것 우선). r_i = heardStart − shownStart.
3. 곡 단위 보정값: 일치한 줄이 6개 이상이고, r 의 중앙값 m, MAD(중앙 절대 편차) ≤ 250ms 일 때만, |m| ≥ 80ms 이면 m 을 추가 이동으로 적용(최대 ±1500ms). 조건 미달이면 적용 안 함.
4. 기록·로그: 곡별 저장(Entry 에 refineMs, refineLines, refineMad) + 로그 한 줄 'lyrics-refine: <videoId> lines=<n> median=<m>ms mad=<mad>ms applied=<y|n> base=<base>'. lyrics-sync 로그의 shift 는 refine 포함 최종값.
5. 수동 보정(manual)·HQ 맵과의 순서: 화면 = base → hq → refine → manual. 사용자가 수동 보정하면 refine 은 유지하고 manual 이 그 위에.
6. 언제 실행: 가사 시각이 정해진 뒤 받아쓰기 단어가 준비되면 1회(이벤트 기반, 타이머·폴링 금지). 같은 곡 재생 중 재측정으로 base 가 바뀌면 다시 계산.
7. 받아쓰기 범위: 지금 받아쓰기가 base=none/ai 경우에만 돈다면, measured 곡에도 앞부분 90초 1회 받아쓰기를 허용(배터리: 곡당 1회, 이미 저장된 결과 재사용, 다운로드 곡은 파일에서). 비용·배터리 영향은 요약에 적을 것.
8. 순수 함수 RefinePolicy.compute(lines, heard) → Result(applied, medianMs, madMs, lines) 로 분리하고 단위 테스트: (a) 모든 줄 -200ms 일정 → +200 적용, (b) 6줄 미만 → 미적용, (c) 반복 후렴이 1.2초 떨어져 두 번 나올 때 가까운 쪽 선택, (d) MAD 400ms(들쭉날쭉) → 미적용, (e) ±1500 상한. 고치기 전에는 RefinePolicy 가 없어 실패해야 한다.

제약: 정렬 수학(ChromaAlignment, fitAi) 변경 금지. sync-safe 스위치 기본값 유지. 배터리 우선. 바꾼 함수의 모든 호출부 재확인. .github/, keys, 서명 수정 금지.
