VERDICT: ISSUES 6
- HIGH — `app/src/main/java/com/music/bitchord/playback/PlaybackService.kt:5683` — The new automatic swap never checks `OriginalVersion.isPinned`, so a search already running when the user taps “Revert to original” can still replace that pinned YouTube stream with a lossless substitute. Fix: bail out before downloading when pinned, as `swapPointFor` does.
- HIGH — `app/src/main/java/com/music/bitchord/playback/AudioCache.kt:2067` — `downloadVerifiedRendition` reuses or resumes any existing `#hifi` entry without proving it was filled by this stream, so a stale partial from another candidate can be spliced or swapped in. Fix: capture the old forced URL before `force` and discard unless it matches this stream, mirroring `swapIn`’s `alreadyFilled` guard.
- HIGH — `app/src/main/java/com/music/bitchord/playback/PlaybackService.kt:5900` — The new swap never calls `watchUpgrade`, so a complete-but-wrong-length or short replacement is adopted and can hit ENDED seconds later with no revert to the old stream. Fix: call `watchUpgrade` after the adopt, or enforce an equivalent duration check.
- MEDIUM — `app/src/main/java/com/music/bitchord/playback/AudioCache.kt:2073` — `downloadVerifiedRendition` and the shared `cacheWholeRenditionDetailed` run `isComplete`, `getCachedSpans`, and metadata mutations on the caller’s Main dispatcher. Fix: wrap the fetch/check body in `withContext(Dispatchers.IO)`.
- MEDIUM — `app/src/main/java/com/music/bitchord/playback/PlaybackService.kt:5838` — The swap polls `playbackState`/`isPlaying` every 20 ms (and 10 ms) for up to 7 s, contradicting the explicit event-based/no-polling battery requirement. Fix: drive readiness from `Player.Listener` callbacks or a state flow instead of `delay` loops.
- MEDIUM — `app/src/main/java/com/music/bitchord/playback/PlaybackService.kt:5751` — `currentPlayingVerification`/`currentIsSubstitute` prefer `StreamChoice` over the decoder snapshot, so a stale substitute choice after a failed/reverted upgrade yields a wrong offset and seeks the new lossless copy to the wrong position. Fix: derive source identity from `NerdStats.current`/`PlayingAudioFormat` first, falling back to `StreamChoice`.
