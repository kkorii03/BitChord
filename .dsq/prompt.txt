[폰 검증 한 번에 — PC(Windows)에서 실행하는 스크립트, 앱 코드 수정 금지]
오늘 밤 사용자가 폰(S24, 무선 ADB, 이미 사용자 설정이 들어 있음)을 PC 에 연결하면 명령 하나로 MV·품질 업그레이드·싱크를 검증한다. 에뮬레이터는 YouTube 음원을 못 받아서 폰으로만 가능하다.
 scripts/phonecheck.py (표준 라이브러리, 실행: tools\python\python.exe -I scripts\phonecheck.py --apk <apk> 또는 --no-install):
 1) adb 연결 확인(없으면 tools\phone_auto.py 실행 — scripts/synctest.py 의 ensure_phone 재사용).
 2) --apk 가 주어지면 adb install -r(설정 유지).
 3) scripts/smoke/songs.txt 를 읽어(형식: id 또는 search:<검색어>, 탭, 종류 mv/hq/cover/plain) 순서대로 재생: id 는 am start VIEW https://music.youtube.com/watch?v=<id> -p com.music.bitchord, search: 는 MEDIA_PLAY_FROM_SEARCH(query) -p com.music.bitchord. 종류별 대기: mv 45초, hq 90초, cover/plain 75초. 재생 전 sync-test.flag 생성·미디어 볼륨 0(끝나면 복구) — scripts/synctest.py 의 방식 재사용.
 4) logcat 을 전체 시간 동안 스트리밍으로 phone-out\phonecheck\logcat.txt 에 저장, 끝나면 synctest/*.wav 를 phone-out\phonecheck\synctest\ 로 pull.
 5) 판정: scripts/smokecheck.py 를 그 로그에 실행(종류별 판정 --songs), 싱크는 scripts/synctest.py 의 채점 함수를 import 해서 cover/plain 곡별 줄 오차(로그의 sync-dump + WAV, Deepgram 키는 keys\deepgram_key.txt 를 읽기만) → phone-out\phonecheck\report.md 하나로 합친다: 맨 위에 MV n/5 통과, HQ accepted 수, 싱크 중앙값·0.3초 이내 비율·곡별 표.
 6) 사용자 폰을 쓰는 중이면 안 되므로 시작할 때 '약 40분 소요' 출력.
 python -I -m py_compile 와 가짜 로그로 판정 단위 테스트(scripts/test_phonecheck.py) 실행. 마지막에 6줄 요약.
