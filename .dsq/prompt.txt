[긴급 버그 — 사용자 실기기: '품질 업그레이드'를 계속 눌러도 안 되고, 자동 업그레이드도 전혀 안 됨. Opus 가 로그로 원인 확정]
사용자 로그(10-26 11:57~12:23): 모든 곡이 'upgrade found: <곡> at FLAC 16-bit 44.1kHz from Monochrome/Qobuz' 다음 약 65ms 만에 'hq-verify: <곡> ... match=0% offset=0 -> rejected' + 'hq-verify: <곡> no reference audio; keeping YouTube'. 즉 고음질 후보는 찾는데 기준(YouTube) 음원 특징을 못 얻어 전부 거절. 손으로 누르면 'manual upgrade ignored ... 20937ms cooldown remaining' 와 토스트 '음질을 확인하는 중이에요. 잠시 후 다시 시도해 주세요'.
원인(코드 확인됨, app/.../playback/smart/HqAudioVerify.kt):
 (1) referenceFeaturesUncached 첫 줄 'if (!PowerState.screenOn) return null' 과 featuresOf(...){ ... && PowerState.screenOn } — 배터리 작업(00e1)이 넣은 화면 꺼짐 차단. 사용자는 대부분 화면 끄고 이어폰으로 들으므로 검증이 영원히 안 된다.
 (2) 기준 실패를 noReference 에 10분(NO_REFERENCE_TTL_MS) 기억 → 화면을 켜고 눌러도 즉시 실패.
 (3) 수동 업그레이드 쿨다운이 이 실패와 겹쳐 버튼이 무반응처럼 보인다.
고칠 것:
 a) 화면 꺼짐 차단 제거. 이 검증은 (곡, 소스, 트랙)마다 한 번이고 결과가 디스크에 저장되므로 비용이 작다. 디코더 동시 사용은 이미 있는 AudioDecoder 전역 세마포어(자동 믹스 분석과 직렬)로 충분 — 없으면 같은 방식으로.
 b) noReference 기억은 '이번 재생 동안'만: 다음 재생 이벤트나 수동 요청 때는 무조건 다시 시도(10분 타이머 의존 금지). 기준 오프닝이 아직 안 왔으면 AudioCache.awaitAnalysisHead 를 수동 요청 때는 더 길게(예: 20초) 기다린다.
 c) 수동 '품질 업그레이드': 쿨다운·noReference 를 무시하고 즉시 검증을 시작, 진행 중이면 같은 작업에 붙는다(중복 실행 금지). 결과를 애플식 문구로 알린다: 성공 '고음질로 전환합니다'(다음 재생 대신 지금 곡이면 기존 규칙대로 안전한 시점에), 원곡 불일치 '이 노래와 일치하는 고음질 버전을 찾을 수 없습니다', 기준 음원 실패 '지금은 음질을 확인할 수 없습니다. 다시 시도하십시오'. 해요체 금지.
 d) 거절 기록: 기준 음원이 없어서(no reference) 실패한 경우는 HqVerificationStore 에 '거절'로 영구 저장하면 안 된다 — 지금 그런 경로가 있으면 막는다. 진짜 불일치(match 낮음)만 거절 저장.
 e) 로그: 'hq-verify: <곡> no reference reason=<head-timeout|no-source|decode-failed|cancelled>' 로 원인 표시.
 f) 다운로드 곡의 자동 교체(HqLibraryUpgrade)도 같은 검증을 쓰므로 함께 살아나는지 확인.
테스트: 순수 판정(수동 요청 시 쿨다운 무시, no-reference 는 거절 저장 안 함)을 shared 함수로 빼서 jvmTest. 컴파일·테스트 직접 실행.
