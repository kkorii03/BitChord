버그(폰 로그로 증명, ship\FIXLIST.md 62번): 자동 믹스(크로스페이드)에서 'crossfade: start ... fade=6000ms' 부터 다음 곡 'play: ... reason=AUTO' 까지 실제 겹침이 계획 fade 와 상관없이 매번 약 18초(46회 중 대부분 17~19초, fade=120ms 인 곡도 15초). 사용자 체감: 섞이는 동안 원래 곡은 거의 음소거, 다음 곡은 아주 작게 들림. vc84(10-27) 표본 1건은 fade 11.3초에 9.8초였음 → 최근 커밋 회귀 의심(git log 로 크로스페이드·automix·ARMING·handoff 관련 최근 변경 확인).
할 일: ① 크로스페이드 시작~손넘김(handoff)~이전 곡 정지까지 상태 흐름과 음량(gain) 곡선을 읽고, 왜 겹침이 18초 고정인지 원인을 코드로 특정해 요약에 적기(추측 금지, 줄 근거). ② 수정 기준: 겹침 = 계획 fade 길이, 나가는 곡은 fade 시작 전까지 원래 음량, 동일 파워 곡선(중간 지점 각 -3dB, 합친 크기 일정), 들어오는 곡은 fade 끝에 반드시 원래 음량(1.0, 음량 맞춤 값 반영) 도달. ③ 로그: 시작·25·50·75%·끝 시점 두 곡 gain 과 실제 겹침 ms 를 한 곡당 2~3줄 이내로.
테스트: gain 곡선 계산 순수 함수(시작 1/0, 중간 ≈0.707/0.707, 끝 0/1, fade 길이 지키기) 단위 테스트.
반드시: 배터리 우선(주기 폴링·타이머 금지, 이벤트 기반). 바꾼 함수의 모든 호출부와 타입을 다시 읽고 확인. 기존 코드 의도(주석)를 지우면 요약에 이유. 다운로드된 곡·커버 곡·MV/노래 버전 판정 경로는 이 작업과 무관하면 건드리지 말 것. 업스트림 v1.8.1 코드 정리·파일 쪼개기 금지. 새 app 테스트는 이름을 요약에 적을 것(CI 목록에 Opus가 추가). 제약: .github/, keys, 서명 수정 금지. 마지막에 10줄 이내로 요약: 수정 파일 / 핵심 변경 / 테스트 결과 / 미해결 문제.
