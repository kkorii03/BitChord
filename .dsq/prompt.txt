MEDIUM — shared/src/jvmSharedMain/kotlin/com/music/bitchord/data/CatalogSongMapper.kt:133 — the persisted cache is still v2, so a `NONE` verdict written under the old 10-second song window for the same id suppresses the new `typeUnknown`/video-window lookup for up to 7 days. MEDIUM — app/src/main/java/com/music/bitchord/playback/SongVersionController.kt:309 — the new `!verifyUnknownDownload` guard bypasses `streamLongDownloadedSong`, the length check that marks a legacy file as MV sound and schedules `MvSoundRedownload`, so an unknown-provenance MV file that is streamed is never queued for replacement. MEDIUM — app/src/main/java/com/music/bitchord/download/Downloads.kt:1446 — `prepare` still decides the song version from only `isVideo`/`typeUnknown`, so a re-download or quality replacement of an unknown-provenance MV row fetches its own video stream again instead of the catalogue release.
