[자동 검증 도구 — 사용자 폰 대신 에뮬레이터 로그로 핵심 3가지를 자동 판정]
배경: 시험판이 나올 때마다 사용자가 직접 써 보고 'MV 재생, 품질 업그레이드 안 됨, 가사 어긋남' 을 발견하고 있다. 에뮬레이터 시험(.github/workflows/ui-tour.yml, 산출물 artifact 'ui-tour' 의 logcat)에서 자동으로 잡아야 한다.
할 일: scripts/smokecheck.py (표준 라이브러리만) 를 만든다. 입력: logcat 파일 경로. 출력: 항목별 PASS/FAIL 표와 종료 코드(하나라도 FAIL 이면 1).
 판정 항목(로그 줄 형식은 저장소 코드에서 grep 으로 확인해 정확히 맞출 것: 'track-summary:', 'song version:', 'audio switch:', 'lyrics-sync:', 'LyricsTiming song-sync:', 'hq-verify:', 'upgrade ', 'next-prep:', 'decode: ', 'FATAL EXCEPTION', 'ANR in'):
 1) MV 재생: track-summary 의 video=y 인 곡, 또는 제목에 '(Official Video)'/'Official Music Video'/'M/V'/'MV' 가 있는데 song version 교체 로그가 없는 곡 → FAIL 목록.
 2) 노래 버전 판정 실패: 'audio switch: no official song match' 개수와 곡명.
 3) 싱크 이상: lyrics-sync/song-sync 의 |shift| > 3000ms 또는 refused-shift → 경고 목록(MV 소리 의심).
 4) 품질 업그레이드: 'hq-verify ... -> accepted' 개수, '-> rejected' 개수, 'decode: hq-verify failed' 개수. accepted 가 0 이고 후보가 1개 이상이면 FAIL.
 5) 튕김·ANR: FATAL EXCEPTION / ANR → FAIL.
 6) 다음 곡 준비: next-prep 의 version= 이 MV id 로 남은 경우.
 또 `--report out.md` 로 마크다운 요약.
 단위 테스트: scripts/test_smokecheck.py 에 작은 가짜 로그로 각 항목 PASS/FAIL 확인(python -m unittest 로 실행해 통과).
 .github/ 는 수정하지 말 것(워크플로 연결은 Opus 가 한다). 사용법을 docs/cleanup/smokecheck.md 에.
