검토 지적:
VERDICT: ISSUES 5
- HIGH `shared/src/jvmSharedMain/kotlin/com/music/bitchord/data/innertube/StreamResolver.kt:918` (+`UnplayableReason.kt:69`): InnerTubeX collapses every `Reason.UNAVAILABLE` (including Korean region blocks) to "This track is unavailable.", which `isDefinitelyGone` treats as gone, and the early throw runs before the existing proxy retry, so region-blocked tracks are marked permanently unplayable and skipped. Fix: do not early-throw on that generic message, or only after the proxy attempt/when no proxy is available, using the `StreamResolveException.Reason`/diagnostics to separate region from takedown.
- MEDIUM `shared/src/jvmSharedMain/kotlin/com/music/bitchord/data/innertube/StreamResolver.kt:604` (also `:643`): Both proxy-race branches still key off `directUnplayable`/`preferredItx` rather than `isTrackSpecific(directUnplayableReason)`, so a claimed/deleted direct refusal with a proxy configured still spends a proxy walk instead of being a one-shot verdict. Fix: gate both proxy branches with `!UnplayableReason.isTrackSpecific(directUnplayableReason)`.
- MEDIUM `app/src/main/java/com/music/bitchord/playback/PrefetchController.kt:235` (wired at `PlaybackService.kt:7974`): The next-prep alternate lookup still uses the 12s `ALTERNATE_LOOKUP_TIMEOUT_MS`, not the new 2.5s definitive timeout, so the read-ahead path that discovers the verdict can block 12s and duplicate the playback-path search, missing the stated 3s target. Fix: pass `DEFINITIVE_ALTERNATE_TIMEOUT_MS` into `PrefetchController` or cancel its search once the row becomes current.
- MEDIUM `shared/src/jvmSharedMain/kotlin/com/music/bitchord/data/innertube/UnplayableReason.kt:96` (and `:153`, used globally at `PlaybackService.kt:5556`): Broad markers such as `"사용할 수 없"`/`"이용할 수 없"` and bare `"not available"` classify any playback exception, so unrelated addon/module errors (e.g. `AddonClient`'s "사용할 수 없는 주소입니다") become permanent track verdicts, marked unplayable and skipped instead of retried/falling back. Fix: restrict message classification to resolver-originated exceptions or narrow the markers to track-specific wording.
- LOW `shared/src/jvmSharedMain/kotlin/com/music/bitchord/data/innertube/StreamResolver.kt:584`: `tryInnerTubeX` still unconditionally records `noteRefused` when the preferred InnerTubeX walk returns null, so track-specific non-gone verdicts (age-restricted/paid) still bench the learned InnerTubeX path, contrary to requirement ④. Fix: skip `noteRefused` when the failure is track-specific.
